# S042 — Podcast contracts, schema and migrations

**Milestone:** MVP-5 Podcasts
**Status:** IMPLEMENTED_UNVERIFIED (desktop + Android verified; iOS build BLOCKED)
**Depends on:** —

## Objective

Establish the podcast data model once, across contracts, desktop libSQL, Android Room and
iOS SQLite, without changing playback or UI behavior. Everything later depends on this
shape.

## Scope and boundaries

- Add `MediaKind`, `PlaybackContext`, `PodcastFeed`, `PodcastEpisode`,
  `PodcastSearchResult`, `PodcastRefreshSummary`, `PodcastImportSummary` and
  `PodcastFeedPatch` to `libs/contracts`; add optional `Track.mediaKind`.
- Add the `podcast` bridge interface and the playback `context` argument to the contract,
  even though the implementation lands later. Older hosts may omit the namespace.
- Desktop migration 6: `media_item.media_kind`, `playback_state.active_context`,
  `podcast_feed`, `podcast_episode`, `podcast_queue_entry`, `podcast_playback_state`,
  `podcast_directory_cache`, and the `media_source.kind='podcast'` rebuild.
- Android Room v6 → v7 and iOS schema 5 → 6 with the same columns/tables.
- Repository helpers for feed/episode/queue state and the episode ↔ `media_item` mapping.
- Reconcile and document the current Android/iOS schema-version mismatch.
- No fetcher, parser, UI or playback wiring in this slice.

## Acceptance gate

- A real v5 desktop fixture (local + demo + Jellyfin sources, queue, downloads, playback
  state) migrates to v6 with byte-for-byte catalog rows and no orphan/lost records.
- The `media_source` rebuild is proven under libSQL foreign-key rules, or a narrowly scoped
  migration-runner fallback is added and tested.
- `media_kind` defaults to `music`; existing music queries, stats and queue behavior are
  unchanged.
- Android v6 → v7 and iOS schema 5 → 6 migrations preserve existing rows; both build.
- `pnpm typecheck` and the affected unit suites pass; a schema parity note is committed.
- Podcast tables are empty and invisible in the UI.

## Required execution steps

1. Add contract types, validators and fixtures first; keep `mediaKind` optional on the wire.
2. Write the desktop migration and a v5-fixture migration test, including the source
   rebuild. Do not edit earlier migrations.
3. Add Android Room v7 entities/DAO/migration and iOS schema 6 statements.
4. Add pure mapping helpers (`episodeToMediaItem`, path-key hashing, status fields) with
   tests.
5. Add repository methods for feeds, episodes, queue and playback state; test transactional
   refresh/removal and orphan cleanup.
6. Run typecheck, contracts/persistence tests and both native builds.
7. Record evidence in `evidence/S042-report.md`.

## Completion rule

VERIFIED only with a migrated real database and passing migration tests on all three
platforms. A compiled schema without a migration test is IMPLEMENTED_UNVERIFIED.
