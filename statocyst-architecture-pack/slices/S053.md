# S053 — Cross-platform podcast verification and release gate

**Milestone:** MVP-5 Podcasts
**Status:** BLOCKED (iOS/CarPlay and hardware/performance gates unresolved)
**Depends on:** S045, S047, S049, S051, S052

## Objective

Prove the whole podcast story on real runtimes, close cross-platform gaps and make the
MVP-5 release decision. This slice may fix defects, but may not add deferred features.

## Scope and boundaries

- End-to-end matrix: add (URL/OPML/Podcast Index), refresh (new/304/failure), stream,
  seek, resume, switch contexts, complete, pin, offline, remove feed/download, restart.
- Performance: 100 subscriptions / 10,000 episodes on the named reference device and
  desktop; feed parse latency, memory, list scroll, database size.
- Security audit: URL guard at every entry point, no raw HTML, no credential/feed-URL
  leakage in logs/support bundles/database, private-network default deny.
- Accessibility and light-theme pass on desktop/Android/iOS.
- Migration replay from real v5/v6/v5 databases.
- Docs: user-facing podcast help, troubleshooting, privacy note, release notes.
- Evidence reports S042–S053 completed; blocked gates recorded exactly.
- No auto-download, background refresh, chapters/transcripts or sync.

## Acceptance gate

- Every item in the MVP-5 release gate (`roadmap/PODCASTS.md` §18) is demonstrated or
  explicitly BLOCKED.
- A fresh install on each platform can subscribe, listen, resume, pin, go offline and
  restart without data loss.
- 100 feeds / 10k episodes meets the measured budget without UI stalls or main-thread
  parsing.
- Security checks pass: SSRF, XXE, raw HTML, secret/feed-URL redaction.
- No music regression in library, queue, radio, playlists, favorites, stats, downloads or
  cache.
- Evidence and artifact links are committed; the roadmap status is updated.

## Required execution steps

1. Run the full E2E matrix on desktop, Android and iOS, including offline/restart.
2. Run the performance fixture and record device/desktop numbers.
3. Run the security and redaction audit with tests.
4. Replay migrations from real databases; verify backups.
5. Run accessibility/theme checks and fix only release-blocking issues.
6. Complete `evidence/S042-report.md`–`S053-report.md`; update the roadmap and release
   decision.

## Completion rule

VERIFIED only when the release gate is fully evidenced. Any partial platform result keeps
MVP-5 at IMPLEMENTED_UNVERIFIED or BLOCKED; it is not shipped as “all platforms”.
