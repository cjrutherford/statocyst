# S049 — Android podcast playback and downloads

**Milestone:** MVP-5 Podcasts
**Status:** IMPLEMENTED_UNVERIFIED (build/unit verified; device background/offline gates pending S053)
**Depends on:** S046, S047, S048

## Objective

Make the native Media3 service authoritative for podcast playback on Android: background
audio, queue, resume, speed, skip intervals and offline pins, with the WebView gone.

## Scope and boundaries

- Native podcast queue and playback state persisted in Room; one active context shared with
  music (start podcast pauses music and vice versa).
- Media3 media session metadata: show name, episode title, artwork, duration, speed.
- Resume writes on pause/seek/switch/teardown and periodic ticks; completion threshold;
  played/completed; mark unplayed from the app.
- Speed and seek-back/forward intervals; lock-screen/headset controls.
- Native download resolver for `sourceKind='podcast'`; pin/unpin; resume/retry; offline
  playback from the protected download.
- Widget/notification reflects podcast context.
- No Android Auto browse (S052), no background feed refresh.
- Keep music behavior and existing Media3 tests unchanged.

## Acceptance gate

- Play an episode, turn the screen off, and confirm background playback continues.
- Kill the WebView/activity and confirm the native service keeps the queue and position;
  relaunch restores the UI.
- Resume after pause, seek, context switch and process restart.
- Completion advances; a completed episode restarts at 0.
- Speed survives track changes; skip-back/forward use the configured interval.
- A pinned episode plays in airplane mode; an unpinned one fails with clear copy.
- Music playback and Android Auto music browse regressions pass.
- Instrumented tests cover queue/resume/context switching; device evidence is recorded.
- Evidence recorded in `evidence/S049-report.md`.

## Required execution steps

1. Add native podcast queue/state persistence and context switching.
2. Wire Media3 metadata, speed and skip commands; test with instrumentation.
3. Add resume writes and completion transitions.
4. Add podcast source resolution to the native downloader and offline path.
5. Run background/process-death/airplane-mode device checks.
6. Record evidence.

## Completion rule

VERIFIED only with screen-off, process-death and offline device evidence. A build plus unit
tests is not enough.
