# S041 — Bathypelagic motion system (2.0.0)

**Milestone:** Polish / daily driver → 2.0.0
**Status:** PLANNED
**Depends on:** S040 (Capacitor performance overhaul, `perf/capacitor-native-parity`)
**Target release:** 2.0.0 (Android versionCode 28; iOS build 28)
**Reference device:** Google Pixel 10 Pro (physical)

## Objective

Make Statocyst feel like it is moving through water, not just wearing an ocean palette.
Add a coherent motion and depth system — page transitions, ambient water, sonar and
bubble feedback — that stays at native frame pacing on the Pixel and keeps the existing
light/dark themes and ocean/bubble identity.

This is a major release because it changes the feel of every screen and ships on top of
the S040 performance overhaul. It is not a decorative layer added after the fact.

## Starting point

- The app already has a strong static language: abyss gradients, cyan sonar rings, pearl
  highlights, violet bloom, floating artwork, card entrance staggers and equalizer bars.
- S040 removed the expensive WebView paint paths: live backdrop blur on native, fixed body
  attachments, pearl blur and the animated play shadow. The 10k-row library is windowed;
  playback position no longer replaces the coarse snapshot.
- There are ~30 ad-hoc animations across components, with no shared duration/easing/scale
  tokens. Page changes are instantaneous `@switch` swaps in `app.component`.
- `NavigationStore` already has a bounded history, so depth/direction can be derived.
- Angular is zoneless and no `@angular/animations` dependency exists. That is an advantage:
  the motion system should use CSS and platform APIs, not a new animation runtime.

## Proof of concept

- Dark/light themes and Full/Native/Reduced tiers, with OS reduced-motion respected.

## Design direction: "Descent"

Four motion primitives, used consistently:

1. **Current** — horizontal drift for lateral navigation (tabs, albums/artists).
   Small travel (8–24 px), long ease-out, no bounce.
2. **Dive / Surface** — entering a deeper view scales the content in slightly and dims the
   edges; going back lifts and brightens. Library is shallow; Queue is mid-water; Now
   Playing is the deep channel.
3. **Sonar** — a single radial pulse used for playback start, track changes and nav
   activation. One ring, not a loop; 600–900 ms.
4. **Buoyancy** — small bubbles and motes that rise slowly in the ambient layer and burst
   from favorite/download feedback. Slow, sparse, never in front of text.

Depth is expressed as light and pressure, not as heavy 3D: darker edges, slower motion,
cooler highlights, a stronger vignette, fewer/faster particles near the surface.

## Effect catalogue and cost tier

Every effect must be defined for three tiers: **A** desktop full, **B** native (Pixel),
**C** reduced motion / low power. The default is B on Capacitor and A on Electron.

| Effect | Where | Tier A | Tier B (native) | Tier C |
| --- | --- | --- | --- | --- |
| Page transition (current/dive) | every view change | 380 ms transform/opacity | 300 ms transform/opacity | 120 ms fade or none |
| Shared artwork morph | library/queue → Now Playing | yes | yes, with fallback | no |
| Nav bubble indicator | tab bar / sidebar | sliding glow + sonar ping | sliding glow | instant active state |
| Ambient caustics | shell background | 2 layers, 24–40 s drift | 1 layer, 32 s drift | static gradient |
| Rising motes | shell background | 16 particles | 8 particles | none |
| Depth vignette | shell | animated by view | animated by view (opacity only) | static |
| Play sonar | play button | one ring | one ring | none |
| Favorite bubble burst | heart | 6 bubbles + scale pop | 4 bubbles + scale pop | scale only |
| Download bloom | download pill | ring bloom | ring bloom | check appears |
| Toast buoyancy | toasts | rise + fade | rise + fade | fade |
| Row/card hover | library | caustic shimmer | none (touch) | none |
| Seek pearl | seek bars | glow on drag | glow on drag | static thumb |

No effect may animate `width`, `height`, `top`, `left`, `background-position`,
`box-shadow` or `filter` on the native tier. Those are the S040 regressions we just removed.

## Motion tokens

Add to `styles.scss` and expose as CSS variables:

```css
--motion-instant: 90ms;
--motion-quick: 160ms;
--motion-base: 240ms;
--motion-page: 320ms;
--motion-page-desktop: 380ms;
--motion-ambient: 32s;

--ease-tide: cubic-bezier(0.22, 0.61, 0.36, 1);
--ease-drift: cubic-bezier(0.4, 0, 0.2, 1);
--ease-bubble: cubic-bezier(0.16, 1, 0.3, 1);

--depth-shallow: 0;
--depth-mid: 1;
--depth-deep: 2;
```

All new transitions must use these tokens. No raw `transition: all` and no per-component
invented durations. The existing entrance animations are migrated to the tokens and reduced
to one-shot only.

## Architecture

### 1. Motion profile

- `main.ts` sets `data-motion="full|native|off"` next to the existing `data-native`:
  - Electron → `full`
  - Capacitor → `native`
  - `prefers-reduced-motion: reduce` → `off` (also reactive to changes)
- A tiny `MotionStore` exposes `enabled`, `tier`, and `prefersReducedMotion`, and reacts to
  `matchMedia` changes. Components read it only when they need to opt out; CSS handles most.
- Settings > Appearance gets a "Motion" segmented control: **System / Full / Reduced**.
  This is optional for the first cut (OS reduced-motion is mandatory); if added it extends the
  `Settings` contract additively and is stored by both bridges.

### 2. Page transitions

- Add a `ViewTransitionService` around `NavigationStore.navigate/back`:
  - if `document.startViewTransition` exists and motion is enabled, wrap the signal update;
  - otherwise apply `data-transition="dive|surface"` to the shell for one animation frame and
    run the same CSS keyframes on the new view;
  - always call `ApplicationRef.tick()` / await the next frame so the snapshot sees the new DOM.
- Direction comes from a depth rank per view:
  `settings=0, library=0, playlists=0, offline=1, queue=2, now=3`.
  Forward (higher rank) = dive; back = surface; lateral = current.
- View Transitions styling:
  - assign `view-transition-name: main-view` to `main#main-content` only;
  - disable the root animation so the sidebar/player bar stay stable;
  - old view: opacity + translateY/scale toward the depth direction;
  - new view: opacity + translateY/scale from the opposite direction;
  - a caustic highlight sweeps across during the transition at low opacity.
- Fallback CSS classes animate the incoming `.view` with the same keyframes, so the
  experience is consistent on older WebViews.
- Shared artwork (stretch): set `view-transition-name: active-art` on the tapped row's
  artwork and on the Now Playing hero for the duration of the transition; remove the name
  afterwards. If the snapshot is unavailable or the row is virtualized away, fall back to
  the normal page transition.

### 3. Ambient water layer

- New standalone `UnderwaterBackdropComponent` rendered once in the shell, fixed behind the
  content, `pointer-events: none`, `aria-hidden`.
- Layers:
  1. static depth gradient (theme-aware);
  2. caustic sheets (pre-rendered radial/conic gradients, `transform` drift);
  3. motes/bubbles (8–16 small elements, `transform: translateY`, opacity fade);
  4. depth vignette (radial gradient whose opacity changes with the active view).
- Render a fixed number of particles and hide the extras with CSS on native rather than
  creating a different DOM tree per platform.
- Pause the whole layer with `data-ambient="paused"` when `document.hidden` and when the
  app is backgrounded. Do not keep animations running off-screen.
- Theme behavior:
  - dark: abyss, cyan/violet bioluminescence, stronger vignette;
  - light: shallow sunlit water, teal/white caustics, softer vignette.
- No `filter: blur`, no `backdrop-filter`, no canvas/WebGL in the first cut. If a caustic
  shader is ever pursued, it goes behind a measured spike and a battery gate.

### 4. Micro-interactions

- Play/pause: a one-shot sonar ring from the button; press uses `transform: scale(.97)`.
- Favorite: heart scale pop and a small bubble burst (4–6 pseudo-elements); reverse on
  unfavorite is a simple scale, no burst.
- Download: the existing pill gets a filling bubble/progress treatment and a bloom on
  completion; the label remains the source of truth for accessibility.
- Nav: a single sliding indicator behind the active item (`transform: translateX`), plus a
  short icon bob while active. No per-item background transitions.
- Toasts: buoyant rise/fade, one at a time stagger.
- Seek: pearl thumb grows and glows while dragging; release returns to rest.
- Queue: current row gets the existing equalizer; new rows use a small stagger (max 4 items
  staggered, then instant) so a 250-track window does not animate forever.
- All one-shot effects respect `prefers-reduced-motion` and the motion profile.

## Phases

### Phase 0 — Motion baseline and guardrails

- Inventory the existing 30 animations; classify each as keep/one-shot/remove.
- Add motion tokens, `data-motion`, `prefers-reduced-motion` wiring and a debug switch
  (`?motion=off` or a `data-motion` override) for measurement.
- Capture pre-change screenshots and frame baselines with S040's `tools/android-perf.sh`.
- Gate: no visual change yet; desktop and native builds pass.

### Phase 1 — Page transitions and nav

- Implement `ViewTransitionService`, depth ranks, dive/surface/current CSS, fallback.
- Add the sliding nav indicator.
- Convert the manual view switches in `app.component` to go through the service without
  changing the view model or back-stack semantics.
- Gate: every view transition < 350 ms on native; no focus loss; back gesture works;
  reduced-motion uses instant changes.

### Phase 2 — Ambient water

- Add `UnderwaterBackdropComponent` with static depth, caustics, motes and vignette.
- Add view-driven depth (`data-depth`) and visibility pausing.
- Gate: no frame drops while scrolling the 10k library; cold start unchanged; battery
  sample over 20 minutes is not worse than S040.

### Phase 3 — Micro-interactions and shared artwork

- Add sonar, favorite bubbles, download bloom, toast buoyancy, seek pearl.
- Add the shared-artwork morph with fallback.
- Gate: every one-shot effect can be disabled independently; no layout shift.

### Phase 4 — Verification

- Pixel 10 Pro: cold start, 10k scroll, page transitions, playback for 20 minutes, battery
  and memory. Record with `tools/android-perf.sh` and screen recordings.
- Electron: full tier; desktop screenshots and reduced-motion pass.
- Add Playwright assertions for transition state, motion-off behavior, and the Now Playing
  layout from S040 still holding.
- Mark S041 `VERIFIED` only with numbers; update S038/S040 links.

### Phase 5 — 2.0.0 release

- Bump Android `versionCode` 27 → 28 and `versionName` 2.0.0; iOS
  `CURRENT_PROJECT_VERSION` 27 → 28 and `MARKETING_VERSION` 2.0.0; align the desktop
  package version.
- Tag `v2.0.0`; the release workflow builds the signed APK/AAB, iOS IPA and Electron
  installers, and uploads the AAB to the Play internal track when credentials exist.
- Release notes lead with "native-parity performance" and "bathypelagic motion"; include
  the motion toggle/reduced-motion behavior.
- Verify checksums and install over 1.9.0 before announcing.

## Acceptance gates

- Page transitions: 300–380 ms, compositor-only, no input blocking, no focus loss.
- 10k-track library scroll remains at S040's p95 (no regression beyond measurement noise).
- Cold start increases by no more than 100 ms p50; ambient layer does not delay first paint.
- Pixel 10 Pro: no visible jank in page transitions or ambient motion; gfxinfo janky-frame
  percentage not worse than S040; 20-minute playback battery not worse than S040.
- `prefers-reduced-motion: reduce`: no ambient drift, no page morph, no bursts; instant or
  <=120 ms fades only.
- Backgrounded app: ambient animations paused; no WebView work when the screen is off.
- Both themes remain legible and keep the ocean/bubble identity; no contrast regressions.
- Desktop tier remains visually richer without becoming a different app.

## Risks and mitigations

- **View Transitions snapshot cost on low-end devices.** Detect support and measure; keep the
  CSS fallback. Never block navigation on the transition promise.
- **Ambient animations drain battery.** Pause on hidden/background, cap particles, no blur,
  no canvas/WebGL initially, and add a reduced-motion path.
- **Motion sickness.** OS reduced-motion is mandatory; in-app Motion setting is a follow-up
  if needed. No parallax on large moving content, no rapid flashing.
- **View transition and Angular zoneless timing.** Update the signal, tick the app, await the
  next frame inside the transition callback; test both directions and rapid tab switching.
- **Shared artwork morph with a virtualized list.** The row may be removed from the DOM before
  the snapshot; always fall back to the normal page transition.
- **Theme contrast.** The ambient layer must not sit behind text at full opacity; keep it
  behind a scrim and test both themes with the existing a11y audit.
- **Scope creep.** The first release uses CSS/platform APIs only; no new dependencies, no
  WebGL, no audio-reactive visuals.

## Release decision

- If S040 has not yet passed its Pixel performance gate, finish that first. 2.0.0 ships both
  S040 and S041 together; do not tag 2.0.0 on headless measurements alone.
- If the user wants the performance fixes sooner, ship 1.10.0 from the S040 branch first, then
  land 2.0.0 as the visual release. The plan defaults to a single 2.0.0.
