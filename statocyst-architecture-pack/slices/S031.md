# S031 — Quality-aware pins

**Milestone:** Rural offline
**Status:** PLANNED
**Depends on:** S030, ADR-035

## Objective
Let a user choose the offline copy's quality — Original, Balanced or Saver — and store
enough metadata to play, label and audit it.

## Scope and boundaries
- `DownloadProfile = original | balanced | saver`.
- Original: `/Audio/{id}/stream?static=true` (unchanged).
- Balanced: AAC 128 kbps. Saver: Opus 96 kbps on Android, AAC 128 on iOS.
- Persist `profile`, `codec`, `bitRate`, `sourceBytes` on the download row (additive migration).
- Per-pin choice and a bulk sheet with estimated size; label the copy in Now Playing.
- The local copy always wins on playback; the master is never modified.

## Acceptance gate
- Original pins are byte-identical to today's behaviour.
- A lossless Saver pin is at most 20% of the original bytes and never larger than the original.
- An interrupted saver pin resumes, or restarts with an explicit warning; no silent corruption.
- Profile/codec/bitrate/size are stored and shown; SHA-256 verification still passes.
- `Range` probe evidence against the target Jellyfin server is recorded in ADR-035.

## Required execution steps
1. Prove Range support for the transcode endpoint, or choose server-side pre-transcode.
2. Add the additive DB migration and contract fields first.
3. Add failing tests for the URL builder, profile persistence and size accounting.
4. Implement, then run affected tests and a device transfer.
5. Record evidence in `evidence/S031-report.md`.

## Completion rule
Do not mark VERIFIED if the saver transfer cannot survive a dropped connection.
