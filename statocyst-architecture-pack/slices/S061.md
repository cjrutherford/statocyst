# S061 — MVP-6 verification, performance and release gate

**Milestone:** MVP-6 Video podcasts
**Status:** PLANNED
**Depends on:** S056–S060

## Objective

Prove the whole video-podcast story on real runtimes, close cross-platform gaps and make
the MVP-6 release decision. This slice may fix defects but may not add deferred features.

## Scope and boundaries

- End-to-end matrix: video RSS add/refresh → play → video/audio-only → background/screen-off
  → PiP → seek → resume → restart; audio/video alternate switch; pin original/audio/
  compressed → offline.
- Performance: screen-off 60-minute audio on Android/iOS; hidden-video CPU/battery on
  desktop; 1080p video playback; large-video pin/quota; compression time/CPU; startup.
- Security audit: SSRF on enclosures/alternates/posters, URL redaction, no-extraction
  artifacts in core bundles, no ffmpeg binary in default desktop/mobile artifacts.
- Accessibility/theme pass on video controls; reduced motion; focus return from PiP.
- Migration replay from real v6 desktop, v7 Android and v6 iOS databases.
- Docs: user help for video podcasts, download sizes and compression, background behavior,
  troubleshooting, privacy note and release notes with platform limitations.
- Evidence S054–S061 completed; blocked gates recorded exactly.
- No YouTube, third-party extractor, live video, general transcoding or embedded mobile
  video.

## Acceptance gate

- Every item in the MVP-6 release gate (`roadmap/VIDEO_PODCASTS.md` §9) is demonstrated or
  explicitly BLOCKED.
- Video RSS podcast plays with background audio on desktop, Android and iOS; restart/resume
  works; no music/audio-podcast regression.
- Audio/video alternate switching works without losing position; feed preference is
  respected; a feed/tier that only exposes video works as video.
- Video-only episodes appear in the list/queue, the Video filter works, and audio-only
  playback of a decodable video container works.
- Pins work for original, audio-only, 480p and 720p; sizes are honest; offline playback and
  cleanup work; cancellation/failure leaves no corruption.
- Screen-off/background evidence exists for Android and iOS on named runtimes; desktop
  minimize/media keys are in E2E. PiP is demonstrated or BLOCKED with a recipe.
- Car surfaces are audio-only and handle a video-only episode gracefully.
- Security and accessibility checks pass; no extraction/transcoder artifact in core builds.
- Performance results are recorded on named references; no arbitrary thresholds.
- Evidence and artifact links are committed; the roadmap/ADR status is updated.

## Required execution steps

1. Run the full desktop/Android/iOS matrix, including background, PiP, filters and offline.
2. Run the performance scenarios and record device/desktop numbers, including compression.
3. Run the security/redaction and packaging audits.
4. Replay migrations from real databases; verify backups.
5. Run the accessibility/theme checks; fix only release-blocking issues.
6. Complete `evidence/S054-report.md`–`S061-report.md`; update the roadmap and release
   decision.
7. If a platform cannot meet video/PiP/background/compression, mark it BLOCKED with a
   reproduction recipe; do not claim parity.

## Completion rule

VERIFIED only when the release gate is fully evidenced. Any partial platform result keeps
MVP-6 at IMPLEMENTED_UNVERIFIED or BLOCKED; it is not shipped as “all platforms”.
