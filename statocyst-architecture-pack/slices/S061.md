# S061 — Android companion, car eligibility and no-extraction audit

**Milestone:** MVP-6 Video podcasts
**Status:** PLANNED
**Depends on:** S057, S060

## Objective

Let Android use the same paired companion over an authenticated LAN (or explicitly record
the platform as BLOCKED), keep car surfaces audio-only, and prove the Android APK contains no
YouTube extraction code.

## Scope and boundaries

- Android companion client: pairing via QR/code, token in Keystore/encrypted preferences,
  localhost/LAN address validation, version negotiation, timeouts and error mapping.
- Source management and classification use the shared renderer + native persistence already
  delivered by S054; no duplicate parser.
- Playback uses the existing Media3 player with a resolved companion stream. Audio-only is
  the default; video requires the native surface from S057.
- Car browse: include YouTube episodes only when they are audio-eligible and the companion
  is reachable. YouTube episodes are streaming-only, so there is no pinned fallback. Hide
  the section with a clear state when the companion is unavailable; no video template, no
  show notes.
- No extraction library, Python runtime, yt-dlp binary or NewPipe Extractor in the APK. No
  bundled GPL plugin in this slice.
- No iOS changes.

## Acceptance gate

- Pairing with the fixture companion over localhost and LAN succeeds; invalid/expired
  codes, wrong version, 401, 429 and timeout show distinct states without leaking the token.
- A YouTube episode added on desktop appears on Android after refresh and plays audio with
  the screen locked; video plays full-screen when requested and detaches on background.
- YouTube episodes are streaming-only: no pin/download action exists, and an offline
  episode without a companion shows the companion-unreachable/streaming-only state, not a
  silent skip.
- Car browse shows only audio-eligible items; no video surface or show notes; unreachable
  companion does not crash or show empty ghost rows.
- `unzip -l`/APK inspection shows no yt-dlp, ffmpeg, Python or NewPipe artifact; a test or
  script asserts this.
- Instrumented tests cover pairing errors, screen-off audio, PiP/video detach and car browse
  filtering. If LAN pairing cannot be validated, the gate is BLOCKED with a reproduction
  recipe.

## Required execution steps

1. Add the Android companion client and secure storage; write fixture-server tests.
2. Wire pairing UI and source refresh through the shared renderer.
3. Verify resolved streaming playback, the absent pin action and screen-off behavior.
4. Add car browse eligibility filtering and tests.
5. Add the APK no-extraction audit.
6. Run Gradle build, unit/instrumentation tests and a named-device scenario.
7. Record evidence in `evidence/S061-report.md`.

## Completion rule

VERIFIED only with a named Android device/emulator, screen-off audio and either working LAN
pairing or an explicit BLOCKED record. APK inspection must pass.
