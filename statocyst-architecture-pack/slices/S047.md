# S047 — Podcast downloads and offline behavior

**Milestone:** MVP-5 Podcasts
**Status:** IMPLEMENTED_UNVERIFIED (offline pin verified; unpinned/Range/quota pend S053)
**Depends on:** S044, S046

## Objective

Let a user pin individual episodes for offline listening on desktop, and make offline
behavior explicit rather than silent. Generalize the download/protocol plumbing without
regressing Jellyfin.

## Scope and boundaries

- Refactor `DownloadService`, `CacheManager` and the protocol handler around a
  `RemoteAudioResolver` used by Jellyfin and podcast sources.
- `ProtocolTrack.remote` becomes a union: Jellyfin (server/item/token/quality) or podcast
  (enclosure URL + safe headers).
- Manual pin/unpin from episode row and Now Playing; size shown when known.
- Reuse the existing `.part` → hash → rename flow, quota, Wi-Fi policy, progress events,
  protected-download rules and native queue (native work follows in S049/S051).
- Offline view groups music and podcast pins; unpinned podcast playback offline explains
  what to do.
- Feed removal asks about downloads; removing a pin keeps the episode row.
- No auto-download, retention policy or background prefetch.

## Acceptance gate

- A pinned episode plays from disk with the network blocked and reports verified offline
  state.
- An unpinned episode offline shows a clear “Download to listen offline” error and does not
  advance the queue.
- Range/seek works on a pinned episode; the protocol precedence is download → cache →
  network.
- Jellyfin downloads, cache and playback regressions all pass.
- Download removal is clean (no orphan file/row); feed removal with downloads follows the
  chosen confirmation.
- Quota and Wi-Fi-only settings apply to podcast pins exactly as to music.
- Interrupted desktop downloads leave no corrupt final file.
- Evidence recorded in `evidence/S047-report.md`.

## Required execution steps

1. Extract the resolver interface and port Jellyfin with no behavior change.
2. Add the podcast resolver and URL revalidation before every fetch/play.
3. Wire pin/unpin UI and offline grouping.
4. Add tests for precedence, cleanup, quota and offline errors.
5. Run the existing download/cache/Jellyfin suites plus the podcast offline E2E.
6. Record evidence.

## Completion rule

VERIFIED only with a real network-blocked playback of a pinned episode and a clean Jellyfin
regression run.
