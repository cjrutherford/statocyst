# S044 — Desktop podcast ingestion, refresh and discovery

**Milestone:** MVP-5 Podcasts
**Status:** IMPLEMENTED_UNVERIFIED (real Podcast Index API not exercised)
**Depends on:** S042, S043

## Objective

Make the Electron host able to search keyless podcast directories (Apple Podcasts and
Fyyd, optional app-configured Podcast Index), resolve the chosen show's feed, fetch, parse,
persist, refresh and expose the whole capability through the typed bridge. This is the
desktop backbone; the UI lands in S045.

## Scope and boundaries

- New `PodcastService` in `apps/desktop-electron/src/main` plus repository use.
- `FeedFetcher`: conditional GET, redirect/timeout/body/content-type limits, per-host and
  global concurrency, jittered backoff, 304/429/5xx handling, `resolved_url`.
- SSRF guard shared with S043: DNS resolution of every address, private/loopback/link-local/
  metadata deny by default, redirect revalidation, optional “allow local network feeds”
  setting.
- Parse in a worker thread so large feeds do not stall the main process.
- Artwork cache (episode then feed, 2 MB, image content-type, local path).
- Refresh scheduler: on add, startup, focus, 15-minute due check, manual, per-feed interval.
- Directory providers: keyless Apple iTunes Search and Fyyd normalization/dedupe; optional
  Podcast Index with developer/environment credentials only. Cache responses and show
  attribution. No user key entry.
- IPC channels and preload `podcast` namespace; typed, validated arguments; no feed body
  accepted from the renderer.
- No renderer views, playback changes or mobile code.

## Acceptance gate

- A local fixture HTTP server proves: add feed, parse, persist, 304, ETag, redirect,
  timeout, 5 MB cap, 429 `Retry-After`, 5xx backoff, private-IP denial and redirect-to-
  private denial.
- Refreshing discovers new episodes, updates changed metadata, preserves resume/played/
  download state and leaves no orphan rows.
- A feed failure is isolated: other feeds still refresh and existing episodes remain.
- Search merges Apple and Fyyd results, dedupes by normalized feed URL, works with one
  provider down, caches for 15 minutes, and exposes source labels.
- Optional Podcast Index results appear only with build/environment credentials and are
  never requested from the user; no secret appears in the database, logs or support bundle.
- Artwork is cached locally and served through the art scheme; a failed image does not fail
  the feed.
- `pnpm typecheck`, host tests and an Electron IPC smoke test pass.
- Record evidence in `evidence/S044-report.md`.

## Required execution steps

1. Add the service skeleton and repository calls; define fetch/schedule error types.
2. Implement the SSRF guard and fetch policy with a local test server.
3. Wire the worker parser and transactional persistence.
4. Add scheduling, backoff and manual refresh.
5. Add optional app-configured Podcast Index client and log redaction.
6. Add artwork cache, directory search providers, IPC/preload and validation.
7. Run the fixture-server matrix and record evidence.

## Completion rule

VERIFIED only with the local-server HTTP matrix and a real refresh cycle. Mock-only fetch
tests do not satisfy the gate.
