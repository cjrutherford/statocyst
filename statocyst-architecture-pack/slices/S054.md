# S054 — Video podcast contracts, schema and migrations

**Milestone:** MVP-6 Video podcasts
**Status:** PLANNED
**Depends on:** MVP-5 S042 (podcast contracts, migration 6, Room v7, iOS schema 6)

## Objective

Establish the video-podcast data model once, across shared contracts, desktop libSQL,
Android Room and iOS SQLite, without changing playback or UI behavior. Everything later
depends on this shape.

## Scope and boundaries

- Add `MediaForm`, `PodcastSourceKind`, `PodcastClassification`, `PodcastEnclosure` to
  `libs/contracts`; extend `Track`, `PodcastFeed` and `PodcastEpisode` additively.
- Add `PlaybackSnapshot.mediaForm`/`presentation`, `PlaybackCommand.setPresentation` and
  `EngineLoadRequest.mediaForm`/`posterUrl` to the contract, even though wiring lands later.
- Add the optional `CompanionBridge` interface and its status/probe/add-source types;
  older hosts may omit it.
- Desktop migration 7: `media_item.media_form`; `podcast_feed.source_kind`,
  `external_id`, `bridge_id`, `default_media_form`, `min_duration_minutes`,
  `include_shorts`; `podcast_episode.media_form`, `alternates_json`, `external_id`,
  `source_page_url`, `poster_url`, `video_width`, `video_height`, `classification`,
  `classification_reason`, `stream_kind`; the media-form index.
- Android Room v7 → v8 and iOS schema 6 → 7 with the same columns/defaults.
- Repository/mapping helpers for episode ↔ media item, alternates serialization and
  classification reason. No fetcher, parser, protocol, UI or playback behavior.
- Do not touch `media_kind` or rebuild `media_source`/queue tables.

## Acceptance gate

- A real v6 desktop fixture (music, RSS podcasts, queue, downloads, cache, playback state)
  migrates to v7 with byte-for-byte unchanged music/podcast rows and no orphans.
- Existing rows read `media_form='audio'`, `classification='declared'`,
  `stream_kind='direct'`; old payloads without the new fields still validate.
- Android v7 → v8 and iOS 6 → 7 preserve rows; both builds pass.
- `alternates_json` round-trips a bounded, validated list; a malformed list fails closed
  and does not lose the episode.
- `pnpm typecheck` and affected suites pass; the schema parity note is updated.
- No UI or playback change is observable.

## Required execution steps

1. Add contract types, validators and fixtures first; keep every new wire field optional
   where an older host could omit it.
2. Write desktop migration 7 with a v6-fixture migration test. Do not edit earlier
   migrations.
3. Add Android Room v8 entities/DAO/migration and iOS schema 7 statements.
4. Add pure mapping/serialization helpers and tests.
5. Add repository read/write methods for the new fields; keep transactions per feed.
6. Run typecheck, contracts/persistence tests and both native builds.
7. Record evidence in `evidence/S054-report.md`.

## Completion rule

VERIFIED only with a migrated real v6 database and passing migration tests on all three
platforms. A compiled schema without a migration test is IMPLEMENTED_UNVERIFIED.
