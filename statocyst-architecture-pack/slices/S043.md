# S043 — Shared podcast feed core

**Milestone:** MVP-5 Podcasts
**Status:** VERIFIED
**Depends on:** S042

## Objective

Make one pure, well-tested TypeScript library responsible for turning hostile RSS/Atom
bytes into a normalized feed and episode set, and for OPML, show-note extraction and URL
classification. No network access in this library.

## Scope and boundaries

- New `libs/podcast-core`: RSS 2.0, Atom 1.0, iTunes namespace, and recognition of the
  Podcast 2.0 namespace for the fields the schema stores.
- Reject `<!DOCTYPE`/`<!ENTITY`; disable entity expansion; cap document size, depth and node
  count.
- GUID fallback, date parsing, duration parsing, enclosure selection, relative URL
  resolution, episode cap (2,000), stable `path_key` hashing.
- HTML-to-text for descriptions, entity decoding, safe link extraction (max 20, HTTP(S)
  only). Raw HTML is never returned for rendering.
- OPML parse/serialize, dedupe and limits (5,000 feeds).
- URL classification helpers: scheme/credential rules, IPv4/IPv6 private/loopback/
  link-local/metadata detection that a host adapter can pair with DNS resolution.
- Add fixtures: real-world RSS, Atom, iTunes-only, Podcast 2.0, malformed, missing GUID,
  bad dates, missing duration, relative enclosure, oversized and XXE payloads.
- No fetcher, scheduler, filesystem, Electron, Capacitor or database code.

## Acceptance gate

- Every fixture produces the expected title, author, image, episodes, GUIDs, dates,
  durations and enclosure URLs.
- XXE/billion-laughs payloads are rejected without expansion; malformed XML returns a typed
  error, never a partial feed that silently loses episodes.
- Refresh parsing is idempotent: the same bytes produce the same `path_key` and episode
  identity; changed titles/art update but identity is stable.
- A feed with 5,000 items truncates to 2,000 newest and reports truncation.
- OPML import/export round-trips nested folders and dedupes; invalid/private URLs are
  reported, not silently added.
- No raw HTML or `javascript:`/`data:` link survives extraction.
- `nx test podcast-core` and `pnpm typecheck` pass.

## Required execution steps

1. Add the library project, tsconfig path and the pinned XML parser dependency; record the
   license and reason in the slice report.
2. Implement the typed parse result and error model; add fixtures and failing tests first.
3. Implement RSS, Atom, namespaces, GUID/date/duration/enclosure normalization.
4. Implement description-to-text and safe links.
5. Implement OPML and URL classification with tests.
6. Run the suite and a fuzz-ish malformed-input pass; record evidence in
   `evidence/S043-report.md`.

## Completion rule

VERIFIED only with the fixture matrix and malformed-input tests passing. A parser that
handles one sample feed is not sufficient.
