# S059 — Companion contract, pairing and desktop client

**Milestone:** MVP-6 Video podcasts
**Status:** PLANNED
**Depends on:** S054

## Objective

Define and exercise the optional Statocyst Companion contract on desktop: authenticated
pairing, health/status, version negotiation and a fixture server, without importing a
YouTube source or adding any extraction dependency to the app.

## Scope and boundaries

- Implement the host-side `CompanionBridge` client: `status`, `pair`, `unpair`, `probe`,
  `addSource` signatures behind the contract; only `status/pair/unpair` are wired in this
  slice, with `probe/addSource` stubs or fixture-only paths.
- Store the bridge URL and token in `safeStorage`; bind localhost by default; require an
  explicit user action for a LAN address. Never write them to the catalog or app state.
- Validate the companion `X-Statocyst-Bridge-Version`, capabilities and response size/time;
  refuse incompatible majors; map errors to the existing `Result` codes.
- Add a fixture companion HTTP server in the test suite (health, pair, revocation, malformed
  version, 401, timeout, oversized response). No live YouTube tests.
- Add Settings/diagnostics UI for pair/unpair/test connection with redacted token display.
- Packaging test asserts no yt-dlp/ffmpeg/Python/NewPipe artifacts in `app.asar` and no
  companion binary in default electron-builder outputs.
- Do not add the YouTube source UI, classification or playback resolution yet.

## Acceptance gate

- Pairing succeeds against the fixture with a valid code and fails cleanly for an invalid,
  expired or reused code.
- The token is stored only in `safeStorage`; it never appears in logs, the support bundle,
  the database or renderer storage. A redaction test proves it.
- A wrong major version, 401, 429, timeout and malformed body each produce a distinct,
  non-leaking error state.
- Unpair clears the token and makes the companion status `configured=false`/`paired=false`.
- LAN mode requires an explicit confirmation and shows the security warning.
- `pnpm typecheck`/tests pass and the packaging audit passes.
- No YouTube extraction dependency appears in any core artifact.

## Required execution steps

1. Add the client and a fixture server; write failing tests for pairing and error mapping.
2. Implement secure storage, version/capability negotiation and timeouts.
3. Add settings/diagnostics UI and redaction tests.
4. Add the packaging audit script/test.
5. Run the desktop suite and a packaged-app smoke for the diagnostics surface.
6. Record evidence in `evidence/S059-report.md`.

## Completion rule

VERIFIED only with fixture-server pairing, a redaction proof and a packaging audit that
searches the actual built artifacts. A client that compiles but has never paired is
IMPLEMENTED_UNVERIFIED.
