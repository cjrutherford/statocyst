# S059 — Video downloads, offline playback and cleanup

**Milestone:** MVP-6 Video podcasts
**Status:** PLANNED
**Depends on:** S055, S056, S057, S058

## Objective

Let users pin video podcast episodes for offline playback through the existing download
pipeline, with honest size/quota behavior, audio-only alternates and clean removal.

## Scope and boundaries

- Extend the direct-enclosure download path (desktop `resolveDirectAudio`, Android
  `DownloadManager`, iOS `DownloadManager`) to accept the selected `MediaForm` and the
  episode's enclosure/alternate URL. Rename the desktop resolver from audio-specific to
  media-specific if that clarifies it.
- Download sheet: show estimated size; offer **Original** and **Audio only** when the feed
  publishes an audio alternate, otherwise **Original video**; warn for large files
  (`> 500 MB` or a quota-based threshold). Compressed presets are added by S060.
- Reuse `.part` → hash → rename, verified-size check, quota, Wi-Fi policy, progress events
  and eviction protection. No new download table.
- `DownloadView.mediaForm` is derived from the joined media item; download stats include
  video bytes.
- Offline playback: a pinned video plays with the video surface; a pinned audio alternate
  plays audio-only. A missing/corrupt pin is reported unverified, never silently played.
- Remove: deleting a pin frees the file and record; removing a feed asks whether to delete
  its pins. No orphan rows.
- Fix Android direct-podcast download parity if it is missing; iOS already has a podcast
  remote path. Add tests for both.
- No YouTube/third-party extraction. No transcoding in this slice; original and
  feed-provided audio alternates only. Compression is S060.

## Acceptance gate

- A 1-hour video fixture pins successfully on desktop and Android/iOS test harnesses; the
  stored size matches the file; the SHA-256 verifies; restart still sees it as pinned.
- An episode with audio+video offers both choices; audio-only pin is smaller and plays
  without the video surface. A video-only episode offers only the full file.
- Quota refusal happens before writing bytes, with a clear message; a mid-download failure
  leaves a `.part` that is either resumed within policy or removed.
- Offline playback works with the network blocked on every platform. A corrupted/missing
  file is reported unverified and can be re-downloaded.
- Removing a pin and removing a feed leave no orphan `download` or `media_item` rows.
- Download stats and the offline view show the correct form and bytes.
- Existing audio podcast and music downloads show no regression.
- Evidence includes a large-file timing/size record, an offline screenshot/video and a
  cleanup check.

## Required execution steps

1. Extend the download source resolver and views with `mediaForm`.
2. Add the download-choice UI and size/quota messaging.
3. Add Android parity for direct podcast enclosures; extend iOS/desktop tests.
4. Add offline, corrupt-file and cleanup tests.
5. Run desktop unit/E2E, Android instrumentation and iOS build/tests.
6. Record evidence in `evidence/S059-report.md`.

## Completion rule

VERIFIED only with an actual large-file pin, offline playback and cleanup on each named
platform. A download that compiles but was never played offline is IMPLEMENTED_UNVERIFIED.
