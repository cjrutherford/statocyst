# S032 — Storage and metered policy

**Milestone:** Rural offline
**Status:** PLANNED
**Depends on:** S030

## Objective
Stop a rural user from filling the device or burning a data cap by accident.

## Scope and boundaries
- Free-space preflight with a 500 MB reserve for pins.
- Configurable pin quota (default 10 GB or 25% of free space, whichever is smaller).
- Metered detection (`NET_CAPABILITY_NOT_METERED`); "Download over Wi-Fi only / Any network".
- Queue state `WAITING_FOR_WIFI`; notification and in-app copy.
- One transfer at a time on weak/metered links; two on Wi-Fi.
- Does not include WorkManager rescheduling (S037) or the Downloads screen (S037).

## Acceptance gate
- A pin that cannot fit is refused with a clear message and no partial file.
- On a metered network the queue waits and resumes on Wi-Fi without losing progress.
- Manual per-network override is remembered.
- Policy decisions are pure functions with unit tests.

## Required execution steps
1. Extract the policy into a pure object with tests.
2. Add settings + native wiring.
3. Add queue states and notification copy.
4. Run unit tests and a device matrix (Wi-Fi, metered, airplane mode).
5. Record evidence in `evidence/S032-report.md`.
