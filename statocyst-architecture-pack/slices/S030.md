# S030 — Size truth: catalog, contract and UI

**Milestone:** Rural offline (post-Polish)
**Status:** IN_PROGRESS
**Depends on:** —

## Objective
Make track size a first-class value everywhere: synced from Jellyfin, carried by the
shared `Track` contract, and visible before a download starts.

## Scope and boundaries
- Sync `MediaSources[0].Size` on Android, iOS and the Electron Jellyfin client.
- Add `sizeBytes` and `bitrate` to `Track`; keep them optional for sources that do not report them.
- Show size on the library row, album/artist detail, selection bar and Offline view.
- No download behaviour changes; no quality profiles; no quota yet.
- Do not change the SQLite schema; `media_item.size_bytes` already exists.

## Acceptance gate
- A synced Jellyfin track reports a non-zero size when the server supplies one.
- Album/artist detail shows a total that matches the sum of its tracks.
- Selecting tracks shows the selected count and total bytes.
- Offline view shows per-track size and the pinned total.
- Contracts, web typecheck and Android unit tests pass.

## Required execution steps
1. Enumerate the mapping points and their fixtures.
2. Add failing tests for the Jellyfin mapping (`Size` present / absent).
3. Implement the smallest contract + mapping + UI change.
4. Run affected typecheck/tests/builds.
5. Record evidence in `evidence/S030-report.md`; mark BLOCKED where a device check is required.

## Completion rule
VERIFIED only with a real synced library showing correct sizes. Otherwise IMPLEMENTED_UNVERIFIED.
