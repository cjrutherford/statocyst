# S057 — Android video presentation, PiP and background audio

**Milestone:** MVP-6 Video podcasts
**Status:** IMPLEMENTED_UNVERIFIED (Android compile/unit tests/assemble pass; PiP + screen-off verified on emulator API 36; visual frame and physical-device matrix open)
**Depends on:** S054, S055

## Objective

Play video podcast episodes on Android through the existing Media3 service, with a
full-screen native video surface, native PiP and audio that continues when the app is
backgrounded or the screen is off.

## Scope and boundaries

- Keep Media3 as the only player and the existing foreground media service as the only
  session. Do not add a second ExoPlayer or a WebView `<video>` player.
- Add a native `PlayerView`/surface managed by the plugin: full-screen launch from Now
  Playing, attach/detach surface, aspect-ratio handling and a poster while loading.
- `setPresentation`/lifecycle: detach the surface on background, audio-only or screen-off;
  keep audio playing. Reattach without losing position.
- PiP: `enterPictureInPictureMode` for video playback when the user backgrounds a video;
  audio-only playback does not enter PiP.
- Media session/notification: show form and video/PiP actions where the platform supports
  them; preserve speed, skip and resume actions.
- Data saver: prefer the audio form when the feed has one and the connection is metered.
- Room v8 is delivered by S054; no schema work here.
- No YouTube/third-party extractor; no extraction in the APK.
- Car surfaces remain audio-only and are out of scope.

## Acceptance gate

- A video podcast fixture plays full-screen; pause/seek/rate/next/previous use the existing
  queue and notification.
- Pressing Home during video detaches the surface and continues audio; returning restores
  video at the same position (or stays audio-only if that is the user's setting).
- Screen-off/60-minute audio playback continues with the screen locked; no video frames are
  decoded while the screen is off.
- PiP works on a supported device/emulator and is absent or gracefully explained when the
  OS capability is missing.
- Audio-only podcasts, music, downloads and the media session show no regression.
- Instrumented tests cover surface detach, background audio, PiP entry where testable, and
  queue restore. Evidence includes a screen recording and a lock-screen screenshot.

## Required execution steps

1. Add the native surface host and plugin geometry/control methods.
2. Wire `setPresentation` and lifecycle detach/attach without touching the queue model.
3. Add PiP parameters and capability reporting.
4. Extend the media session/notification for video/presentation actions.
5. Add instrumentation and a physical/emulator run with screen-off evidence.
6. Run Gradle build, unit/instrumentation tests and the existing podcast regression suite.
7. Record evidence in `evidence/S057-report.md`.

## Completion rule

VERIFIED only with screen-off audio, background/foreground surface behavior and PiP
evidence on a named Android device or emulator API level. Compilation alone is not enough.
