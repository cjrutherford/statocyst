# S046 — Two-context playback, resume, speed and skip

**Milestone:** MVP-5 Podcasts
**Status:** IMPLEMENTED_UNVERIFIED (service + UI E2E verified; full restart/completion device gates pending S053)
**Depends on:** S042

## Objective

Add a persistent podcast playback context beside the music queue while keeping exactly one
authoritative audio engine and one active context per instance. Episodes must resume across
restarts and pauses.

## Scope and boundaries

- Extend `playback-core` with context-aware helpers that reuse the existing pure queue
  model; keep `applyQueueCommand` behavior for music unchanged.
- `PlaybackService` owns both queues, two persisted playback states, `active_context`, and
  routes `command(command, context?)`.
- Inactive-context queue commands mutate without switching audio; play/seek/load switches
  context and pauses the outgoing one.
- Snapshot/queue events gain `context` and `active`; existing music callers remain source
  compatible.
- Engine gains `playbackRate` on load and a `rate` command; renderer audio engine applies it.
- Per-episode resume writes on pause/seek/context switch/track change/shutdown and every
  10 s; completion threshold; played/completed transitions; manual mark unplayed.
- Podcast queue seeding from the selected show/list; predictable auto-advance.
- Renderer `PodcastPlaybackStore`, player-bar podcast mode, Now Playing podcast layout and
  speed/skip controls.
- No downloads, feed refresh or mobile native work (S047+).

## Acceptance gate

- Music playback, queue, shuffle, repeat and persistence tests are unchanged.
- Starting a podcast pauses music; starting music pauses the podcast; both queues survive
  restart and resume at the right position.
- A podcast episode resumes after pause, seek, context switch and app restart.
- An episode marked completed starts at 0 next time; an in-progress episode resumes.
- Completion marks played/completed and advances to the next queue entry.
- Speed persists across track changes; skip buttons seek by the configured seconds.
- Commands against the inactive queue do not change the active audio source.
- Desktop Playwright E2E proves switch → resume → completion; unit tests cover the state
  machine.
- Evidence recorded in `evidence/S046-report.md`.

## Required execution steps

1. Add failing tests for two contexts, switch behavior, resume and completion in

6. Record evidence.
