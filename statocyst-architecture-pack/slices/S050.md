# S050 — iOS podcast data and ingestion

**Milestone:** MVP-5 Podcasts
**Status:** IMPLEMENTED_UNVERIFIED (iOS CI build passes; runtime/device evidence pending)
**Depends on:** S044, S045

## Objective

Bring the shared podcast library to Capacitor iOS with URLSession fetching, keyless
directory search, SQLite persistence and the shared renderer UI. Mirror Android's data
behavior, not just its feature list.

## Scope and boundaries

- `StatocystDatabase` schema 5 → 6: podcast tables and `mediaKind` filtering, preserving
  existing rows.
- Plugin methods matching S048: `fetchPodcastFeedXml`, generic keyless directory fetch,
  `savePodcastFeed`, `savePodcastEpisodes`, `listPodcastFeeds`, `listPodcastEpisodes`,
  `updatePodcastFeed`, `removePodcastFeed`, `setEpisodePlayed`, `cachePodcastArtwork`.
- URLSession fetch policy: conditional GET, timeouts, body cap, redirect cap, SSRF guard,
  content-type checks.
- Shared TS bridge orchestration: native fetch → shared parse → native persist; foreground
  refresh of due feeds; manual refresh.
- Artwork cached into app support.
- No native playback queue changes here (S051), no CarPlay browse (S052).

## Acceptance gate

- On a simulator/device, add a feed, persist it, restart and see the same library.
- Refresh discovers new episodes and preserves resume/played/download fields; failed feeds
  are isolated.
- Private/loopback URLs and redirects to private addresses are blocked.
- Keyless directory search returns Apple/Fyyd results through URLSession; no user key is
  required.
- Music `listTracks`/stats/browse return no podcast rows.
- Schema 5 → 6 migration preserves existing rows.
- iOS build/tests pass.
- Evidence recorded in `evidence/S050-report.md`.
