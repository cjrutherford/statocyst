# S060 — Desktop YouTube source, classification and resolved playback

**Milestone:** MVP-6 Video podcasts
**Status:** PLANNED
**Depends on:** S055, S059

## Objective

Let a desktop user add a YouTube channel, playlist or single video as a video podcast
source, classify podcast-length items, refresh metadata and play audio/video through the
paired companion — with clear failure states and no extraction in core.

## Scope and boundaries

- Add the "Add video podcast" flow (separate from RSS discovery), gated on a paired
  companion. Probe first, show title/author/item count/eligible count/duration sample and
  the legal notice; require confirmation before writing.
- Source kinds: `youtube-channel`, `youtube-playlist`, `youtube-video`. Channel RSS is used
  for newest items; the companion supplies duration/backfill. Playlists/videos use the
  companion only.
- Classification: declared/manual/inferred/excluded with the ordered rules in
  `roadmap/VIDEO_PODCASTS.md` §5.8; default 20 minutes, "podcast length" preset 45, Shorts
  and live/upcoming excluded, manual override sticky.
- Episode mapping and refresh: `youtube://video/<id>` enclosure, external id, source page,
  thumbnail/poster, `stream_kind='resolved'`, idempotent upsert, bounded backfill (100
  initial, 2,000/feed), no auto-download.
- Playback: protocol YouTube remote kind calls the host resolver; resolver calls the
  companion `/v1/media` with the token, caches in memory only, and proxies Range. Audio is
  the default form; video is requested only in video presentation.
- UI: source badge, classification reason, refresh/remove source, "Not a podcast" action,
  companion-unreachable banner. YouTube episodes expose **no pin/download action**; only RSS
  video episodes (S055/S056) can be pinned.
- No Android/iOS changes. No live-YouTube CI. No core extraction dependency.

## Acceptance gate

- Fixture companion: probe a channel, add it, classify a 72-minute item as inferred, exclude
  a 3-minute Short, play audio in the background, switch to video, seek/rate, restart and
  resume.
- A single video URL requires confirmation and shows its duration; a 10-minute video below
  the threshold is rejected unless the user explicitly overrides.
- Channel RSS refresh adds new items and keeps old ones, resume/played state and queue;
  companion failure does not delete rows or the queue.
- Resolved URLs are memory-only, expire correctly, and never appear in logs, the support
  bundle or the database. A redaction test proves it.
- Companion 401/404/429/timeout map to the defined user-facing errors; no retry storm.
- Removing a source cleans up episodes/media items; no orphans. YouTube episodes never
  create download rows, so there is no download prompt for this source kind.
- The pin/download control is absent for YouTube episodes; an offline attempt shows the
  streaming-only state.
- `pnpm typecheck`, unit/integration suites and the desktop E2E (with the fixture companion)
  pass. Live YouTube is a recorded manual result, not a CI claim.
- A packaging audit confirms no extraction artifacts in core.

## Required execution steps

1. Add source contracts/adapters and classification tests with synthetic metadata.
2. Implement probe/add/refresh and transactional persistence.
3. Implement resolved stream resolution and protocol playback with the fixture companion.
4. Add the UI flow, legal notice, settings and error states.
5. Extend E2E with the fixture companion and background playback scenarios.
6. Run a time-boxed live probe/playback against the named companion version; record exact
   date/region/result or BLOCKED.
7. Record evidence in `evidence/S060-report.md`.

## Completion rule

VERIFIED only when the fixture-companion E2E passes and a live YouTube result is recorded
(non-blocking for the release decision, but its status must be explicit). A live failure
does not invalidate the contract; it must not be reported as working.
