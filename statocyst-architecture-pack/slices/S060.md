# S060 — Download compression for video podcasts

**Milestone:** MVP-6 Video podcasts
**Status:** PLANNED
**Depends on:** S059

## Objective

Offer space-saving download copies for video podcast episodes: audio-only, 480p and 720p,
using platform-native transcoding where available and a clearly gated desktop path.

## Scope and boundaries

- Add fixed compression presets to the pin sheet:
  - **Audio only** — M4A/AAC, mono 64 kbps or stereo 96 kbps for spoken word.
  - **480p** — MP4/H.264 + AAC, ~800 kbps.
  - **720p** — MP4/H.264 + AAC, ~1.5 Mbps.
  - **Original** — untouched publisher enclosure (existing S059 path).
- Do not expose arbitrary ffmpeg arguments, codecs, resolutions or bitrates.
- Android: `androidx.media3.transformer.Transformer` for audio-only and video presets,
  run in the background download queue, with progress/cancel.
- iOS: `AVAssetExportSession` (`AppleM4A` for audio, 480p/720p presets for video), with
  progress/cancel and a temp output.
- Desktop: use a user-provided/system `ffmpeg` in v1. Probe availability at startup or on
  first use; if absent, disable compressed choices with an explanation while leaving
  original and feed-provided audio alternates available. Bundling ffmpeg is out of scope.
- Output flow: download source to `.part` → optional transcode to a temp file → verify
  size/hash → rename to the final download path. A failed/cancelled transcode keeps the
  original when it already completed, or leaves no committed row; never leave a corrupt
  final file.
- Record the chosen variant in the download record (`profile`/`container` plus a small
  `variant` column if needed; add migration only if the existing fields cannot represent
  the preset).
- Do not transcode during playback; compression is a download-time operation only.
- No YouTube/third-party source, no media editor, no live transcode.

## Acceptance gate

- A 1-hour 720p fixture compresses to a smaller file, plays back with correct duration and
  seeking, and the reported size matches the file.
- Audio-only output is smaller and plays in the audio-only UI without a video surface.
- 480p/720p outputs are labelled accurately and do not upscale a smaller source.
- Cancelling mid-transcode leaves no committed download and no corrupt final file; a
  failure after the source download keeps the original when policy allows, with a clear
  message.
- Desktop without ffmpeg shows the compressed options disabled and still downloads the
  original/audio alternate. Desktop with a configured ffmpeg completes the same presets.
- Android/iOS use native transcoders; no new extraction dependency appears in the build.
- Quota/size calculations use the expected output size and are checked after completion.
- Existing music/audio-podcast downloads and playback show no regression.
- Evidence includes before/after sizes, compression duration, a playback check and a
  cancellation test on each named platform.

## Required execution steps

1. Add the preset/variant contract and download-sheet UI behind the S059 pin flow.
2. Implement the Android Transformer adapter with progress/cancel.
3. Implement the iOS AVAssetExportSession adapter with progress/cancel.
4. Implement the desktop ffmpeg adapter and the no-ffmpeg disabled state.
5. Add verification/cleanup for compressed outputs and the download record.
6. Test quality/size, cancellation, quota and offline playback on all three platforms.
7. Record evidence in `evidence/S060-report.md`.

## Completion rule

VERIFIED only when a real compressed file plays offline on each named platform, or a
platform is explicitly BLOCKED with a reproduction recipe. A transcode that runs but was
never played back is IMPLEMENTED_UNVERIFIED.
