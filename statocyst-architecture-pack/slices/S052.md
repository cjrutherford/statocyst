# S052 — Podcast browse in Android Auto and CarPlay

**Milestone:** MVP-5 Podcasts
**Status:** BLOCKED (iOS/CarPlay dependent; Android Auto podcast browse pending)
**Depends on:** S049, S051

## Objective

Expose the native podcast library in the existing car surfaces without booting the WebView:
browse subscriptions, continue listening and episodes, and control playback safely.

## Scope and boundaries

- Android Auto `MediaLibraryService`/browse tree:
  - Podcasts root → Continue Listening, Subscriptions → Episodes.
  - Episode metadata, played/progress, downloaded indicator.
  - Play/resume/seek/speed where the car surface supports it.
- CarPlay `CPListTemplate`:
  - Podcasts → Continue Listening, Subscriptions → Episodes.
  - `CPNowPlayingTemplate` shares the existing `PlaybackManager`.
- Native persisted rows only; no feed fetch, show-notes rendering or external links.
- Driver-safe text truncation and bounded lists.
- Offline state is explicit.
- No new server API; no new WebView dependency.

## Acceptance gate

- Android Auto (Desktop Head Unit and a real phone where available) browses to an episode
  and plays/resumes it without WebView startup.
- CarPlay simulator browses and plays/resumes an episode; Now Playing reflects state.
- Both surfaces show the correct downloaded/offline state and do not offer unavailable
  actions.
- Music browse/playback regressions pass on both surfaces.
- If a head unit or entitlement gate is unavailable, the slice is BLOCKED with a
  reproduction recipe, not marked complete.
- Evidence recorded in `evidence/S052-report.md`.

## Required execution steps

1. Add native browse nodes/queries for podcasts.
2. Wire selection to the native podcast context and resume.
3. Add CarPlay templates and Now Playing sharing.
4. Test with Desktop Head Unit / CarPlay simulator; attempt real-device evidence.
5. Record evidence and any external blockers.

## Completion rule

VERIFIED only with car-surface browse and playback evidence. A simulator-only CarPlay result
is acceptable where Apple entitlement/head-unit gates are external, but must be stated.
